# 基础 Service 运营与调用指标本地验证指南

## 1. 前置条件

- Go 1.25、Node.js 22、pnpm 11；
- 本地已存在八个独立仓库：`starcat-api-kit`、六个 `starcat-*-api` 与 `starcat-admin-console`；
- 六服务必须先能解析 `starcat-api-kit v0.3.0`。正式使用时先发布 API Kit，再更新六服务依赖；开发期可用 Go workspace 指向本地 API Kit，禁止向仓库提交 `replace`。

## 2. 六服务配置

每个服务都新增独立 `METRICS_STORE_FILE`。业务库和指标库不能共用同一文件：

```dotenv
METRICS_STORE_FILE=./data/<service>-metrics.db
```

Test Profile 默认端口保持 5001–5006。按各服务 `.env.example` 配置原有 API Key、Admin Key、GitHub Token 等变量；本专项没有改变凭据边界。启动后分别验证：

```bash
curl -fsS http://127.0.0.1:5001/healthz
curl -fsS -H "Authorization: Bearer <API_KEY>" \
  "http://127.0.0.1:5001/internal/metrics/summary?range=24h" | jq .
```

将端口替换为 5002–5006，可验证其余服务。指标每 30 秒刷入 SQLite；刚产生请求时最多等待一个刷新周期。

## 3. Admin Console

```bash
cd /Users/dong4j/Developer/1.AI/ai-incubator/Starcat/supports/starcat-admin-console
pnpm install
pnpm dev
```

打开 `http://127.0.0.1:5173`：

1. 在 **Profiles** 为 Test 环境配置六个本地 URL 与 Key；
2. 进入 **Services**，逐个确认健康、业务统计、Data resources 与 Registered actions；
3. 进入 **API monitoring**，确认 1h/24h/7d/30d/180d、Service 和 Metric 筛选；
4. 调用几次服务 API，等待最多 30 秒后刷新，确认曲线和 Route ranking 出现；
5. 切换 Production 时，仅验证已有 Gateway；页面应继续通过 BFF 注入 `X-SC-Svc`，浏览器网络请求中不得出现 API Key。

## 4. 自动化验收

六个 Go 服务和 API Kit 分别执行：

```bash
go test ./...
go vet ./...
```

Admin Console 执行：

```bash
pnpm check
pnpm test:e2e
```

通过标准：所有命令成功，Playwright 包含 API Monitoring 曲线与路由排行用例；BFF 单测确认固定资源路径和指标 fan-out 不向浏览器返回测试密钥。
