# Starcat Admin Console 数据平台本地使用指南

本文用于在管理员 Mac 上启动 PostgreSQL Catalog、连接 `starcat-recsys-trainer`，并通过 Web
控制台验证 BigQuery 额度、下载任务和 SQL Lab。该功能只支持本机回环地址，不是公网 SQL
服务，也不属于 Test / Production 六个业务 API。

## 1. 前置条件

- Docker Desktop 已启动；
- Node.js 22+、pnpm 11；
- `supports/starcat-recsys-trainer` 已执行 `uv sync --all-groups`；
- `gcloud` 已安装，并已为 BigQuery 建立 Application Default Credentials（ADC）；
- 当前账号可在指定 billing project 中创建 BigQuery Query Job。

首次配置 ADC：

```bash
gcloud auth application-default login
gcloud auth application-default set-quota-project <GCP_PROJECT_ID>
gcloud services enable bigquery.googleapis.com --project <GCP_PROJECT_ID>
```

验证 Trainer CLI：

```bash
cd ../starcat-recsys-trainer
uv sync --all-groups
./.venv/bin/starcat-recsys bigquery quota-usage \
  --billing-project <GCP_PROJECT_ID> \
  --location US \
  --format json | jq .
```

## 2. 配置控制台

回到 `starcat-admin-console`：

```bash
cp .env.example .env.local
```

编辑 `.env.local`：

```dotenv
STARCAT_DATA_PLATFORM_DATABASE_URL=postgres://starcat:starcat@127.0.0.1:55432/starcat_data_platform
STARCAT_TRAINER_ROOT=../starcat-recsys-trainer
STARCAT_BQ_BILLING_PROJECT=<GCP_PROJECT_ID>
STARCAT_BQ_LOCATION=US
```

`.env.local` 已被 Git 忽略。`pnpm dev` 与 `pnpm start` 会在文件存在时自动读取它。不要把
ADC 文件、Token 或其它密钥复制进项目目录。

## 3. 启动

启动 PostgreSQL：

```bash
pnpm data-platform:up
docker compose ps
```

等待 `data-platform-postgres` 显示 `healthy`，再启动控制台：

```bash
pnpm install
pnpm dev
```

浏览器打开 `http://127.0.0.1:5173/data-platform`。顶栏应显示
`Local data platform`，而不是 Test / Production 开关。

生产构建的本机验证方式：

```bash
pnpm build
pnpm start
```

然后打开 `http://127.0.0.1:8787/data-platform`。

## 4. 页面能力

### 4.1 月度额度

页面展示当前 billing project 在 `US` location 的 query job 数、billed bytes、剩余额度和
使用比例。WatchEvent 与 PushEvent 共用同一份月度额度，BFF 只查询一次，并在 30 秒内复用
任务状态快照，避免页面轮询放大 BigQuery 元数据查询。

### 4.2 下载任务

WatchEvent / PushEvent 卡片展示：

- 当前 `running` / `stopped` 状态；
- 2016-01-01 至 2026-08-25 的总分区数与完成数；
- 最后完成分区和 checkpoint 累计预计扫描量；
- `start`、`stop`、`restart` 固定动作。

动作执行前必须二次确认。控制台不会自行实现下载，而是调用 Trainer 对应脚本；screen、
checkpoint、外接磁盘挂载校验、后台额度监控和断点续传规则保持不变。`restart` 会短暂中断
对应下载 worker，验证页面时不要随意点击。

### 4.3 SQL Lab

建议先用零扫描 SQL 验证链路：

```sql
SELECT 1 AS ok
```

操作顺序：

1. 输入 SQL 和单次 billed bytes 上限；
2. 点击 **Dry run**；
3. 确认预计扫描量、引用表和 SQL hash；
4. 在未修改 SQL 与预算的情况下点击 **Execute**；
5. 在页面下方查看字段、结果行、processed bytes 和 billed bytes。

安全限制：

- 只允许一条 `SELECT` 或 `WITH ... SELECT`；
- 首期只允许引用 `githubarchive` 公共数据集；
- 单次预算最大 10 GiB；
- 最多返回 200 行、2 MiB；
- SQL 编辑后立即作废原 dry run，正式查询还会在 Trainer 内重新 dry run；
- SQL 通过 `0600` 临时文件传给 Trainer，任务结束、失败或取消都会删除；
- 查询结果只在 BFF 内存保留 10 分钟，刷新或重启后可能不可恢复。

## 5. Job 审计

Recent jobs 来自 PostgreSQL 表 `data_platform_jobs`，只保存：

- action id、状态、阶段与时间；
- input hash、SQL hash 和 BigQuery job id；
- estimated / processed / billed bytes；
- 稳定错误码和不含敏感内容的错误摘要。

Catalog 不保存 SQL 正文、结果行、真实数据目录、日志路径或 ADC。可用以下命令检查表结构和
脱敏记录：

```bash
docker compose exec data-platform-postgres \
  psql -U starcat -d starcat_data_platform \
  -c 'SELECT action_id, state, sql_hash, estimated_bytes, billed_bytes, created_at FROM data_platform_jobs ORDER BY created_at DESC LIMIT 10;'
```

## 6. 验证清单

```bash
pnpm check
pnpm exec playwright install chromium
pnpm test:e2e
```

人工检查：

- 页面显示正确 billing project 和 location；
- 两类下载任务状态与脚本 `status --json` 一致；
- `SELECT 1 AS ok` dry run 为 0 B；
- Execute 返回一行 `ok = 1`，processed / billed bytes 均为 0 B；
- Recent jobs 出现 dry-run 与 query 两条成功记录；
- PostgreSQL 查询中不存在 SQL 正文字段。

## 7. 停止与故障排查

停止控制台使用当前终端的 `Ctrl+C`。停止 PostgreSQL：

```bash
pnpm data-platform:down
```

该命令保留 Docker volume。不要执行 `docker compose down -v`，除非明确要删除本机 Job
Catalog。

常见问题：

- `DATA_PLATFORM_NOT_CONFIGURED`：检查 `.env.local` 三个必填项并重启控制台；
- `EADDRINUSE 127.0.0.1:8787`：先用 `lsof -nP -iTCP:8787 -sTCP:LISTEN` 查明占用者，不要盲目结束未知进程；
- `QUOTA_QUERY_FAILED`：重新验证 ADC、billing project 和 BigQuery API；
- SQL job 失败：先降低预算范围或改为单日分区 dry run；页面不会回显 Trainer stderr，避免日志泄露 SQL 或凭据；
- 下载卡片失败：直接运行对应脚本的 `status --json` 检查 checkpoint 与外接磁盘状态。
